# BJ-15: Move the server to Supabase Edge Functions

## Brief

<!-- Gate 1. Small: what, why, done-when, and the test that should fail first. Full: see gw-brief. -->
Move the assistant (status, ask, report) and the reminder sender from Next API routes to two Supabase Edge Functions (ask, reminders-send) built from the same TypeScript, now under supabase/functions/_shared/ (Supabase's documented sharing pattern; imports from outside supabase/ need an experimental deploy flag). Shared code stays runtime-neutral (Web Crypto replaces node:crypto; web-push loads as npm:web-push in the Deno adapter). Adapters map Supabase's injected env, force production behaviour, and handle CORS from ASSISTANT_ALLOWED_ORIGINS. Cutover is the owner's switch: Next routes stay; the client uses NEXT_PUBLIC_ASSISTANT_URL when set, reminders.yml uses REMINDERS_URL when set. A deploy Action runs db push then functions deploy on merge to main and skips until its secrets exist; README lists the one-time cutover starting with migration repair for the six hand-run migrations. Out of scope: Supabase Cron, deleting the Next routes, Expo code, behaviour changes. Done when lint, typecheck, vitest, build, e2e, deno check and deno test pass and a local Deno smoke shows CORS, status, fail-closed ask and the cron secret check. Owner pre-approved (autopilot to PR).
